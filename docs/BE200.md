# Intel BE200 (Wi-Fi 7, Bz/Gl) — Port Notes and Status

Status: **experimental, taken automatically like the other cards (Concurrent & on demand), not yet run on a real card.** If it fails, the Start menu's *nekodrop - restore Windows Wi-Fi* gives the card back to Intel's driver; please post a diagnostic report either way.
Monitor/inject, MLD concurrent Wi-Fi station (2.4/5 GHz, WPA2/WPA3, RX Block
Ack, TLC rate control, UMAC scan v17) are implemented; AWDL A-MPDU and the
kernel driver are not. Compiled and struct-checked offline without BE200
hardware; real-silicon bring-up has not yet been run.

---

## 1. Hardware Family and PCI IDs

Intel Wi-Fi 7 cards belong to the **Bz** device family (`IWL_DEVICE_FAMILY_BZ`
in Linux `drivers/net/wireless/intel/iwlwifi/cfg/bz.c`).

| Card | PCI ID | Form factor | MAC type | RF type | Firmware prefix | Status in nekodrop |
|---|---|---|---|---|---|---|
| **Intel BE200** (incl. Killer BE1750w/x, subsys `0x1773`/`0x1774`) | `8086:272B` | Discrete PCIe (`iwl_gl_mac_cfg`) | `GL` (`0x47`) | `FM` (`0x112`) | `iwlwifi-gl-c0-fm-c0-` | Experimental (`intel-be-exp`, active, `--family be200`) |
| Intel BE201 / BE202 / BE401 | `8086:A840`, `8086:7740`, `8086:4D40` | Integrated CNVi (`iwl_bz_mac_cfg`) | `BZ` (`0x46`) / `BZ_W` (`0x4B`) | `FM` (`0x112`) | `iwlwifi-bz-b0-fm-c0-` | Not implemented (`intel-be`) |
| Intel BE211 | `8086:A840`, `8086:7740` (with WH CRF) | Integrated CNVi (`iwl_bz_mac_cfg`) | `BZ` (`0x46`) | `WH` (`0x113`) | `iwlwifi-bz-b0-fm-c0-` / `wh` | Not implemented (`intel-be`) |

Discrete BE200 (`iwl_gl_mac_cfg` + `iwl_rf_fm`) transport parameters from Linux
`cfg/bz.c`:

- `device_family = IWL_DEVICE_FAMILY_BZ`
- `integrated = false`
- `umac_prph_offset = 0x300000` (same as AX210)
- `xtal_latency = 12000`
- `low_latency_xtal = true` (discrete card that *still* sets
  `SOC_CONFIG_CMD_FLAGS_LOW_LATENCY` alongside `SOC_CONFIG_CMD_FLAGS_DISCRETE`)
- `ltr_delay = IWL_CFG_TRANS_LTR_DELAY_NONE` (no host LTR CSR write)
- `mac_addr_from_csr = 0x30` (vs `0x380` on 22000/AX210)
- `min_txq_size = 128`, `max_tfd_queue_size = 65536` (same wrap as AX210)

BE201/BE211 CNVi cards are **not** included in this slice: they require
separate `bz-b0-fm-c0` / `wh` firmware images, integrated `ltr_delay = 2500`,
and CNVi CRF/step-config quirks that cannot be verified without hardware.

Core-release `iwlwifi-gl-c0-fm-c0-c101.ucode` .. `-c109.ucode` also exist in
`linux-firmware` for Linux's newer `iwlmld` driver, which uses a different
boot/init sequence (`IWL_INIT_PHY` instead of `INIT_NVM`).

**Why API 100 (`iwlwifi-gl-c0-fm-c0-100.ucode`) is chosen:**

1. It stays on the `iwlmvm` init handshake (`INIT_EXTENDED_CFG_CMD(INIT_NVM)` +
   `NVM_ACCESS_COMPLETE` -> `INIT_COMPLETE_NOTIF`) — the same flow OpenBSD
   `if_iwx` uses on Bz API 100 and that `iwxradio` already implements.
2. It embeds the entire PNVM inside TLV 74 (`IWX_UCODE_TLV_PNVM_DATA`,
   295,744 bytes, 16 SKUs, all `(mac=0x47, rf=0x112)`), so `fetch-deps.ps1`
   only needs one firmware file.
3. Its `RLC_CONFIG_CMD` version is 3 (RLC fully offloaded to firmware; no host
   `RLC_CONFIG_CMD` needed).
4. Its section counts (29 LMAC, 19 UMAC, 23 paging; max section 32,768 bytes;
   IML 13,944 bytes) fit directly inside `iwx_context_info_dram` (32 entries per
   array).
5. Note on capability bitmask: API 100 sets capability bit 128 (`MAX_CAPA`),
   which overflows `Firmware::capa[16]` (bits 0..127). `Firmware::capa` is
   widened to 24 bytes (192 bits).

## 3. PNVM: Embedded and Fragmented

All BE200 images advertise `IWX_UCODE_TLV_CAPA_FRAGMENTED_PNVM_IMG` (capability
bit 32). Unlike AX210 (which copies the selected SKU's `SEC_RT` sections into
one contiguous DMA buffer and writes its PA to `prph_scratch.pnvm_cfg.pnvm_base_addr`),
fragmented PNVM works as follows (verified in Linux `fw/pnvm.c` and OpenBSD
`if_iwx.c`):

1. Source bytes come from TLV 74 (`IWX_UCODE_TLV_PNVM_DATA`) inside the `.ucode`
   image, falling back to an external `iwlwifi-gl-c0-fm-c0.pnvm` file if absent.
2. Parse the PNVM container for the SKU matching `_sku_id[0..2]` (from
   `ALIVE`'s `sku_id`). Each `IWX_UCODE_TLV_SEC_RT` payload inside that SKU is
   copied into its own DMA buffer (for GL/FM API 100: at most 2 chunks, max
   single chunk 30,240 bytes, max total 31,896 bytes).
3. Write each chunk's physical address into a 256-byte
   `iwx_prph_scratch_mem_desc_addr_array` (`uint64_t mem_descs[32]`).
4. Set `prph_scratch.ctrl_cfg.pnvm_cfg.pnvm_base_addr` to the descriptor
   array's physical address, and `pnvm_size` to the total payload size in bytes
   across all chunks.
5. Ring the PNVM doorbell via `write_umac_prph(UREG_DOORBELL_TO_ISR6,
   UREG_DOORBELL_TO_ISR6_PNVM)` (unchanged from AX210; wait for
   `PNVM_INIT_COMPLETE_NTFY`).

Because `iwxradio` calls `_dma.trim()` right after `alloc_rings()`, chunk
buffers and the descriptor array are pre-allocated in `alloc_rings()` based on
a quick scan of the PNVM container's maximum chunk count and chunk sizes.

## 4. API 68 vs API 100 (MLD Command Set)

Existing `iwxradio` targets firmware API 68 (legacy MAC/binding/station
commands). BE200 API 100 advertises `IWX_UCODE_TLV_CAPA_MLD_API_SUPPORT` (bit
110) and replaces the MAC, binding, and station management commands.

Parsed command/notification versions from `iwlwifi-gl-c0-fm-c0-100.ucode`:

| Command / Notification | Group:ID | API 68 (`iwxradio`) | API 100 (BE200) | Change required for monitor/inject |
|---|---|---|---|---|
| `ALIVE` | `0x0:0x01` | notif v5 (128 B) | notif v7 (144 B) | Prefix is compatible with `iwx_alive_resp_v5` (`plen >= sizeof(...)` already accepts it) |
| `SOC_CONFIG` | `0x2:0x01` | cmd v2 | cmd v2 | Set `LOW_LATENCY` flag even when `!_integrated` (`_card.low_latency_xtal`) |
| `NVM_GET_INFO` | `0xc:0x02` | cmd v1 / notif v4 | cmd v1 / notif v4 | Same `iwx_nvm_get_info_rsp` |
| `MCC_UPDATE` | `0x1:0xc8` | notif v4 (20 B hdr) | **notif v8 (24 B hdr)** | `cap` widened from `uint16_t` to `uint32_t` with 2-byte padding before it (`iwx_mcc_update_resp_v8`) |
| `PHY_CONTEXT_CMD` | `0x1:0x08` | cmd v3/v4 (32 B) | cmd v6 (32 B) | Same 32-byte `iwx_phy_context_cmd`; set `rxchain_info = 0` when `RLC_CONFIG >= 2` |
| `RLC_CONFIG_CMD` | `0x5:0x08` | n/a | cmd v3 | Version >= 3 means RLC is offloaded to firmware (send only if version == 2) |
| `MAC_CONTEXT_CMD` -> **`MAC_CONFIG_CMD`** | `0x1:0x28` -> `0x3:0x08` | legacy `iwx_mac_ctx_cmd` | **cmd v3 (52 B)** | Replace with `iwx_mac_config_cmd`: `id_and_color=0`, `mac_type=LISTENER (2)`, `local_mld_addr`, `MAC_CFG_FILTER_*` bits |
| `BINDING_CONTEXT_CMD` -> **`LINK_CONFIG_CMD`** | `0x1:0x2b` -> `0x3:0x09` | legacy `iwx_binding_cmd` | **cmd v7 (208 B)** | Replace with `iwx_link_config_cmd`: (1) `ADD` link 0 unbound (`phy_id = 0xffffffff`), (2) `MODIFY` inactive to bind `phy_id = 0`, (3) `MODIFY` active (`ACTIVE \| RATES_INFO`) |
| `ADD_STA` -> **`STA_CONFIG_CMD`** | `0x1:0x18` -> `0x3:0x0a` | legacy `iwx_add_sta_cmd` | **cmd v2 (104 B)** (v1: 96 B) | Replace with `iwx_sta_cfg_cmd_v2`: monitor STA (`sta_id = 2`, `link_id = 0`, `STATION_TYPE_BCAST_MGMT`) and AP peer STA (`sta_id = 0`, `link_id = 1`, `STATION_TYPE_PEER`); generic cmd status |
| `REMOVE_STA` -> **`STA_REMOVE_CMD`** | `0x1:0x19` -> `0x3:0x0c` | legacy `iwx_rm_sta_cmd` | **cmd v1 (4 B)** | `iwx_remove_sta_cmd { uint32_t sta_id; }` |
| `SCD_QUEUE_CFG` -> **`SCD_QUEUE_CONFIG_CMD`** | `0x1:0x1d` -> `0x5:0x17` | `iwx_tx_queue_cfg_cmd` (24 B) | **cmd v3 (36 B) / notif v2 (8 B)** | `iwx_scd_queue_cfg_cmd` (`ADD` with `sta_mask`, `flags = 0`; explicit `REMOVE` before `STA_REMOVE_CMD`); same 8-byte `iwx_tx_queue_cfg_rsp` |
| `ADD_STA_KEY` / `MGMT_MCAST_KEY` -> **`SEC_KEY_CMD`** | `0x1:0x17` / `0x1:0xcf` -> `0x5:0x18` | legacy per-type commands | **cmd v1 (80 B)** | Unified `iwx_sec_key_cmd` (`ADD` / `REMOVE`, `sta_mask`, `key_id`, `IWX_SEC_KEY_FLAG_*` for PTK, GTK, and IGTK) |
| `ADD_STA` (RX BA) -> **`RX_BAID_ALLOCATION_CONFIG_CMD`** | `0x1:0x18` -> `0x5:0x16` | legacy `ADD_STA` modify | **cmd v2 (16 B) / notif v1 (4 B)** | `iwx_rx_baid_cfg_cmd` (`ADD` returns `baid < 32`; `REMOVE` by `sta_id_mask` + `tid` on v2 or `baid` on v1) |
| `TLC_MNG_CONFIG_CMD` | `0x5:0x0f` | cmd v3/v4 | **cmd v4 (28 B)** | Same `iwx_tlc_config_cmd_v4` layout (`sta_rate_control` already handles v4) |
| `SESSION_PROTECTION_CMD` | `0x3:0x05` | cmd v1 (24 B) | **cmd v2 (24 B)** | Same `iwx_session_prot_cmd`, with `id_and_color = fw_link_id` (link 1) instead of `mac_id` when cmd version >= 2 |
| `TXPATH_FLUSH` | `0x1:0x1e` | cmd v2 (8 B) | **cmd v2 (8 B)** | Same `iwx_tx_path_flush_cmd`; MLD teardown flushes without legacy `ADD_STA(DRAIN_FLOW)` |
| `SCAN_CFG_CMD` / `SCAN_REQ_UMAC` | `0x1:0x0c` / `0x1:0x0d` | v3 / v14 | **v5 (12 B) / v17 (1940 B)** | `SCAN_CFG_CMD` v5 deprecates `bcast_sta_id` (leave 0); `SCAN_REQ_UMAC` v17 keeps v14 struct size, moves band into `channel_config.flags[31:30]` (`v5.psd_20 = 0`), and uses `link_id` in `scan_start_mac_or_link_id` |
| `TX_CMD` / `TX_RSP` | `0x1:0x1c` | cmd v8 / notif v6 | cmd v10 (28 B) / notif v8 (44 B) | Same `iwx_tx_cmd_gen3` and `iwx_tx_resp` layouts; `iwx.cpp` already uses `rate_n_flags` v2 when `tx_ver > 8` |
| `RX_MPDU` | `0x1:0xc0` | notif v3 | notif v3..v10 | Same `iwx_rx_mpdu_desc` v3 layout; monitor RX includes trailing FCS (`awdl::strip_valid_fcs` already handles this) |
| `POWER_TABLE` / `BT_CONFIG` / `TX_ANT_CFG` / `MCAST_FILTER` / `SF_CFG` | `0x1:*` | same | v7 / v6 / v1 / v1 / v3 | Same struct layouts |

**Not ported (explicitly gated off on MLD/Bz):**
- AWDL RX Block Ack (`add_rx_ba`) and A-MPDU TX (`agg_setup`): would need
  MLD peer `STA_CONFIG_CMD` + `RX_BAID_ALLOCATION_CONFIG_CMD` + `SCD_QUEUE_CONFIG_CMD`
  on the AWDL listener link.
- Fast-send TX window (`--tx-window`) and kernel driver (`nekodrop-wlan.sys`).

## 5. Transport Differences (AX210 vs Bz)

Derived from Linux `drivers/net/wireless/intel/iwlwifi/pcie/` (`trans.c`,
`trans-gen2.c`, `ctxt-info-v2.c`, `rx.c`, `tx-gen2.c`) and OpenBSD `if_iwx.c`.
Every change below is gated on `_card.bz`.

| Area | 22000 / AX210 (`!bz`) | Bz / BE200 (`bz`) |
|---|---|---|
| **MAC access lock/unlock** (`nic_lock`/`nic_unlock`) | Set/clear `CSR_GP_CNTRL` bit 3 (`MAC_ACCESS_REQ`); poll `MAC_CLOCK_READY` (bit 0) & `!GOING_TO_SLEEP` (bit 4) | Set/clear `CSR_GP_CNTRL` bit 21 (`BZ_MAC_ACCESS_REQ`); poll `MAC_STATUS` (bit 20) |
| **SW reset** (`start_hw`, `stop`, proxy `close_ops`) | `CSR_RESET |= SW_RESET` (`0x80`), wait 5 ms | `CSR_GP_CNTRL |= BZ_SW_RESET` (`BIT(31)`), wait 20 ms |
| **APM init** (`apm_init`) | `CSR_GP_CNTRL |= INIT_DONE` (bit 2), poll `MAC_CLOCK_READY` (bit 0) | `CSR_GP_CNTRL |= BZ_MAC_ACCESS_REQ \| MAC_INIT` (bits 21, 6), poll `MAC_STATUS` (bit 20) |
| **APM stop / bus master stop** (`apm_stop`, proxy `close_ops`) | `CSR_RESET |= STOP_MASTER`, poll `MASTER_DISABLED`, clear `CSR_GP_CNTRL & INIT_DONE` | `CSR_GP_CNTRL |= BUS_MASTER_DISABLE_REQ` (bit 29), poll `BUS_MASTER_DISABLE_STATUS` (bit 28), wait 20 ms, clear `MAC_INIT` (bit 6) and `BZ_MAC_ACCESS_REQ` (bit 21) |
| **Firmware kick** (`load_firmware`) | `write_umac_prph(UREG_CPU_INIT_RUN, 1)` | `wr(CSR_FUNC_SCRATCH /* 0x2c */, 0x01010101)` then `setb(CSR_GP_CNTRL, ROM_START /* BIT(7) */)` |
| **RX completion descriptor** (`_rx_used`) | `iwx_rx_completion_desc` (32 bytes/entry) | `iwx_rx_completion_desc_bz` (**4 bytes/entry**: `uint16_t rbid; uint8_t flags; uint8_t reserved;`) |
| **RX doorbell** (`load_firmware`, `poll`) | `wr(RFH_Q0_FRBDCB_WIDX_TRG, idx)` | `wr(HBUS_TARG_WRPTR /* 0x460 */, idx \| ((0u + 512u) << 16))` |
| **TX byte-count table** (`bc_tbl`) | 1024 entries (2 KiB, 1 page) | `TFD_QUEUE_BC_SIZE_BZ = 4096` entries (**8 KiB, 2 contiguous pages**) |
| **MAC address CSR base** (`nvm_get`) | `0x380` (`OTP` `0x380/0x384`, `STRAP` `0x388/0x38c`) | `0x30` (`OTP` `0x30/0x34`, `STRAP` `0x38/0x3c`) |
| **Error table minimum address** | `>= 0x400000` | `>= 0xD0000` |
| **LTR configuration** (`set_ltr`) | Write `CSR_LTR_LONG_VAL_AD` on discrete AX210 | No host write (handled by hardware/firmware) |
| **Interrupt / ALIVE / SW_ERR polling** | `UREG_CHICK = MSI_ENABLE`, poll `CSR_INT` (`ALIVE`, `SW_ERR`, `HW_ERR`) | **Unverified without hardware** — see Section 6 |

## 6. What Cannot Be Verified Without Hardware

Do not guess around these items; verify them first on a real BE200 card:

1. **Interrupt cause latching without PCI MSI-X (`CSR_INT` vs `CSR_MSIX_HW_INT_CAUSES_AD`)**:
   - `iwxradio` does not register PCI interrupts through `winawdl_regproxy`; it
     writes `UREG_CHICK = UREG_CHICK_MSI_ENABLE`, masks interrupt lines, and
     polls `CSR_INT` for `ALIVE` / `SW_ERR` / `HW_ERR` (RX completions are
     polled directly from DMA memory in `_rx_stat`).
   - On Bz, Linux normally runs with MSI-X enabled and reads
     `CSR_MSIX_HW_INT_CAUSES_AD` (`0x2808`) where `SW_ERR` moved from bit 25 to
     **bit 5** (`MSIX_HW_INT_CAUSES_REG_SW_ERR_BZ = BIT(5)`). Linux still
     retains a `!msix_enabled` fallback writing `UREG_CHICK_MSI_ENABLE` and
     reading `CSR_INT`, so `iwxradio` keeps that path and also checks
     `CSR_MSIX_HW_INT_CAUSES_AD` (`ALIVE` bit 0, `SW_ERR_BZ` bit 5, `HW_ERR`
     bit 29) when polling on Bz.
   - **Risk:** If real BE200 silicon refuses to raise `ALIVE` or drops RX
     notifications unless PCI MSI-X is configured in PCI config space,
     `driver/regproxy` will need MSI-X enablement or a different `UREG_CHICK`
     configuration.
2. **Windows driver handoff / warm reset**:
   - After stopping Intel's Windows Wi-Fi 7 driver (`Netwtw14.sys`), whether
     `CSR_GP_CNTRL` `BUS_MASTER_DISABLE_REQ` + `SW_RESET` leaves the GL/FM chip
     in a clean D0 state (including `CSR_DBG_HPET_MEM_REG`, RFKILL, and
     `prph_scratch.ctrl_cfg.step_cfg` / `reduce_power_cfg` left zero) can only
     be confirmed on hardware.
   - Linux `iwl_pcie_ctxt_info_v2_alloc` populates `step_cfg` from CNVi/CNVr
     registers on integrated Bz, and zeroes it on discrete GL unless UEFI BIOS
     tables exist. Whether API 100 firmware asserts on zero `step_cfg` or zero
     `reduce_power_cfg` on Windows BE200 must be checked on hardware.
3. **MLD listener behaviour for AWDL**:
   - Changing the listener's MAC address (`set_address`) in MLD requires
     deactivating the link, modifying `local_link_addr`, and reactivating the
     link (documented in Linux `mac-cfg.h`: `local_link_addr` is ignored on an
     active link), alongside modifying `local_mld_addr` in `MAC_CONFIG_CMD`.
     Latency and firmware stability of cycling link 0 during AWDL address
     rotation need hardware testing.
   - Whether an MLD `LISTENER` MAC auto-ACKs unicast frames addressed to
     `local_link_addr` (needed by AWDL PSF/data frames) and whether
     `MAC_PM_POWER_TABLE` / `SF_CFG` / `MCAST_FILTER` / `BT_CONFIG` are
     accepted cleanly alongside an MLD listener must be verified on hardware.
   - Linux's `iwl_mvm_mld_add_int_sta_to_fw` sets `cmd.mfp = 1` on
     `STATION_TYPE_BCAST_MGMT` when `STA_EXP_MFP_SUPPORT` (capa bit 114) is
     advertised; we mirror that, and whether raw unencrypted AWDL action/data
     injection via `IWX_MONITOR_STA_ID` succeeds on API 100 needs hardware
     verification.
4. **MLD concurrent Wi-Fi station (`sta_*` + UMAC scan v17)**:
   - **SCD queue v3 (`SCD_QUEUE_CONFIG_CMD` `0x05:0x17`)**: verify that both
     monitor (`sta_id = 2`) and AP (`sta_id = 0`) TVQM queues allocate cleanly
     with `flags = 0`, return 8-byte `iwx_tx_queue_cfg_rsp`, and tear down
     cleanly via `IWL_SCD_QUEUE_REMOVE` before `STA_REMOVE_CMD` across repeated
     rejoins.
   - **Dual-PHY / dual-link coexistence (Link 0 listener + Link 1 BSS_STA)**:
     verify that activating MAC 1 / Link 1 on PHY 1 alongside MAC 0 / Link 0 on
     PHY 0 (both same-band and cross-band 2.4 GHz + 5 GHz, noting `-100.ucode`
     does not advertise `CDB_SUPPORT`) time-shares cleanly under dynamic quota
     without `SF_CFG` or firmware asserts.
   - **Keys & PMF (`SEC_KEY_CMD` v1 + `STA_CONFIG_CMD` `mfp`)**: verify CCMP
     PTK/GTK encryption/decryption offload (`RX_MPDU` `DEC_DONE`/`MIC_OK` bits),
     WPA3/PMF `IWX_SEC_KEY_FLAG_MFP` on pairwise and IGTK keys (plus `rx_seq`
     handling for IGTK), and clean key removal on rekey and `sta_leave()`.
   - **RX Block Ack & TLC (`RX_BAID_ALLOCATION_CONFIG_CMD` v2 + `TLC_MNG_CONFIG_CMD` v4)**:
     verify BAID allocation (`baid < 32`) and removal by `(sta_id_mask, tid)`,
     and that firmware rate control works for HT/VHT non-MLO AP links.
   - **UMAC scan (`SCAN_CFG_CMD` v5 + `SCAN_REQ_UMAC` v17)**: verify that
     setting `bcast_sta_id = 0`, `scan_start_mac_or_link_id = 0`, and
     `band << 30` in `channel_config.flags` runs without firmware error and
     delivers beacons/probe responses + `SCAN_COMPLETE_UMAC`.
   - If the station fails on real hardware, the service falls back to on-demand
     mode automatically.
5. **BE201 / BE211 CNVi (`8086:A840`, `7740`)**:
   - Not wired up yet; CNVi CRF identification and `bz-b0-fm-c0` / `wh`
     firmware bring-up need CNVi hardware.
